# Storefront

E-commerce storefront, frontend only. The backend is mocked in the browser with MSW. The full plan and wireframes: https://claude.ai/artifact/DA7CFYDZjwZVNFdKGTUhCo

## Commands

- `pnpm dev` - dev server on 5173
- `pnpm check` - typecheck, lint, format check, unit tests. Must pass before every commit.
- `pnpm e2e` - Playwright against a dev server on port 5317
- `pnpm format` - Prettier write

pnpm only, never npm or npx (use `pnpm exec` / `pnpm dlx`).

## Versions - read before writing code

Training data mixes old APIs for these libraries. Check `package.json` and use the current major only.

- React 19. No `forwardRef` in new code (ref is a prop), no `React.FC`.
- React Router v8 in data mode: `createBrowserRouter` from `react-router`, `RouterProvider` from `react-router/dom`. `react-router-dom` no longer exists. Routes use `Component` / `ErrorBoundary` / `loader` keys; error boundaries read the error with `useRouteError()`.
- TanStack Query v5: object signatures only, `isPending` not `isLoading` for first load, `queryOptions()` factories, `placeholderData: keepPreviousData`.
- Tailwind v4: CSS-first config in `src/index.css`. There is no `tailwind.config.js`; don't create one.
- shadcn/ui (radix-nova style): add components with `pnpm dlx shadcn@latest add <name>`, never hand-write them. They import `cn` from the `cn` package. Don't edit files in `src/components/ui` unless fixing a real bug there.
- MSW v3: `http`, `HttpResponse`, `delay` from `msw`. Unhandled requests are configured with `onUnhandledFrame` (not `onUnhandledRequest`). The worker script is served by the `msw/vite` plugin; don't run `msw init` or commit `public/mockServiceWorker.js`.
- Zod v4: `z.email()`, `z.url()`, `z.int()`, `z.iso.datetime()`, `z.stringbool()`.
- Vitest 5, Playwright, oxlint (not ESLint).

## Mock API

- Everything lives under `/api`. Handlers in `src/mocks/handlers`, state in `src/mocks/db.ts` (persisted to localStorage), catalog generated by `pnpm generate:catalog` into `src/mocks/data/catalog.json`.
- Request and response shapes are the zod schemas in `src/lib/schemas`. The app parses every response with them.
- Guest carts are identified by the `X-Cart-Id` header, signed-in users by `Authorization: Bearer <token>`. Login and register accept `guestCartId` to merge the guest cart.
- Errors are `{ error: { code, message, fieldErrors?, unavailableItems? } }` with codes from `apiErrorCodeSchema`.
- Demo account: `demo@storefront.test` / `password123`. Card `4000000000000002` always declines.
- The dev toolbar (bottom left, dev only) sets latency and error rate. Tests run with zero latency.

## Folder layout

- `src/app/` - router, providers, layout and app-level routes. The only layer that composes features.
- `src/features/<feature>/` - everything for one feature: `api.ts` (query options, fetchers, mutations), components, hooks, tests next to the code.
- `src/components/ui/` - shadcn primitives only. `src/components/` - shared app components.
- `src/lib/` - cross-feature code: zod schemas (`lib/schemas`), pricing, the http client (`request`, `ApiError`) and the query client.
- `src/mocks/` - MSW handlers, in-memory db, seed data.
- `src/test/` - test setup and helpers. `e2e/` - Playwright specs.

Features may import from `components`, `lib` and their own folder. Cross-feature imports go through the other feature's public `api.ts` only. `src/app` may import anything; nothing imports from `src/app`.

## Code rules

- Named exports only. No default exports outside config files.
- No `any`, no non-null `!`. `as` casts only for `as const`. Narrow with zod or type guards instead.
- Every API response is parsed with its zod schema at the fetch boundary. Types come from `z.infer`, never written by hand alongside a schema.
- Server state lives in TanStack Query only. Zustand is for UI state (drawer open, toasts); never copy API data into it.
- Route loaders don't fetch directly. They call `queryClient.ensureQueryData(xQueryOptions(...))` and components read the same options with `useSuspenseQuery`. Loader factories take the query client (`categoryLoader(queryClient)`), live in `features/<feature>/loaders.ts` (not in component files, which breaks Fast Refresh), and are wired up in `createRoutes(queryClient)` in `src/app/router.tsx`. Give each loader route a `HydrateFallback` skeleton.
- Query functions don't pass TanStack's `signal` to `request`. Loaders and components share queries, and an unmounting observer would cancel a fetch a loader is awaiting (this broke the home page under StrictMode).
- Query keys come from the feature's key factory and include every input that changes the result.
- Filter, sort, page and search state lives in the URL, parsed leniently (bad values are dropped, never errors) by `features/catalog/listing-params.ts`. Prices in the URL are whole dollars; the API takes cents. Filter changes push history with `preventScrollReset`; paging scrolls to the top and focuses the heading.
- Change search params through `useSearchParamsUpdate` (`features/catalog/use-search-params-update.ts`), never a bare `setSearchParams(updater)`. React Router's updater sees the last rendered URL, so a second change made while a loader runs drops the first.
- Product variant selection (`?color=&size=`) lives in the URL too, parsed by `features/catalog/variant-selection.ts`. It replaces history so Back leaves the product.
- Money is integer cents everywhere. Format only at render via the shared formatter. Totals come from one pure function.
- Every view that loads data has designed loading, empty and error states. No bare spinners on full pages; use skeletons that match the layout.
- Accessibility is part of done: semantic elements, labels on every input, visible focus, keyboard support, focus management for drawers, dialogs and step changes.
- No dead code, unused exports, commented-out code or TODOs.

## Tests

- Unit and component tests with Vitest + Testing Library. Query by role and accessible name, assert what the user sees. Don't test implementation details.
- Network goes through MSW handlers in tests too. Never mock `fetch` or query hooks directly.
- Render routes with `renderRoute(path)` from `src/test/render.tsx`: real routes, StrictMode, memory router, fresh query client with retries off. Override endpoints per test with `server.use(...)`.
- After anything that navigates, wait for the UI (`findBy*` or `waitFor`), not just the URL: the URL updates before React renders the new page.
- Each user flow gets a Playwright spec in `e2e/`.
- Bugs: write a failing test or Playwright repro first, then fix the root cause, then confirm the repro passes.

## Git

Work on `dev`. Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `ref:`), one small change per commit. Never commit to `main`; `pnpm release` handles that. `CHANGELOG.md`, if it ever exists, is generated - don't edit it.
